# TransitOpt API contract

All routes below are under `/api`, use the existing configurable HTTP Basic authentication, and return JSON. Original VisionX APIs remain available.

* `GET /network`: `{coordinate_system:"illustrative_canvas",width:800,height:600,source,disclaimer,stops:[{id,name,x,y,essential}],routes:[Route],segments,corridors,cameras}`. Route fields: `id,name,color,current_buses,current_variant_id,capacity,bus_capacity,min_buses,max_headway_minutes,corridor_id,stop_ids,required_stop_ids,geometry:[{x,y}],variants:[{id,name,geometry,stop_ids,segment_ids,cycle_minutes,distance_km,validated}],source`.
* `GET /routes`: `{routes:[Route]}`; `/routes/{id}` returns Route. `GET /stops`: `{stops:[...]}`. `GET /cameras`: `{cameras:[{id,name,stop_id,corridor_id,roi,status,source_type}]}`. `PATCH /cameras/{id}` accepts `{roi:[x,y,width,height]}` normalized 0–1, or null to clear.
* `GET /dashboard/summary`: `{source,data_labels,settings,kpis,traffic,forecast,plan,recommendations,system}`. KPIs `available_buses,allocated_buses,reserve_buses,forecast_passenger_demand,capacity_shortfall,average_waiting_time_minutes,fleet_utilization_pct,high_congestion_corridors,active_ai_recommendations` are computed. `plan` is optimizer evaluation of current allocations.
* `GET /traffic/corridors`: `{corridors:[{id,name,route_ids,congestion_score,category,source,timestamp,vehicle_count,people_count,average_speed_kmh,queue_length,method,data_quality}]}`; `/traffic/summary` adds totals and events. `/traffic/events` returns `{events:[...]}`.
* `GET /demand/history?route_id=R02&stop_id=S02&limit=48`: forecasting service history. `POST /demand/forecast` accepts `{route_id:"R02",stop_id:null,horizon_minutes:60,forecast_at:null}` returns `{id,route_id,stop_id,horizon_minutes,predicted_passengers,baseline_passengers,available_capacity,capacity_shortfall,capacity_surplus,history,model_version,evaluation_metrics,source,data_source}`. Horizons 30/60/120. `GET /demand/forecasts`: `{forecasts:[...]}`.
* `POST /optimization/run` or `/simulator/run` accepts `{name:"My scenario",fleet_size:28,reserve_fleet:4,horizon_minutes:60,demand_multiplier:1.2,traffic_level:"high",event_intensity:"none",solver_time_limit_seconds:5,weights:{...}}`; all fields optional. Returns stored optimizer result `{id,run_id,scenario_id,feasible,solver_status,routes:[{route_id,buses,variant_id,headway_minutes,frequency_per_hour,capacity,demand,unserved_demand,coverage_pct,reason}],totals,baseline,comparison,warnings,constraints,assumptions,recommendations:[...],config}`. `GET /optimization/results/{id}` same. `GET /simulator/scenarios`: `{scenarios:[...]}`. `GET /simulator/results/{id}` stored scenario including `baseline,optimized,inputs,result`.
* `GET /recommendations`: `{recommendations:[{id,run_id,route_id,status,proposed_buses,proposed_variant_id,reason,current_buses,...}]}`. POST `/{id}/approve`, `/{id}/reject` optional `{note:"..."}`; `/{id}/activate-simulation` activates the complete plan only once all changed-route recommendations in its run are approved. Pending, rejected, stale or infeasible plans return HTTP409. `POST /optimization/results/{id}/approve` approves all pending entries; `/activate-simulation` atomically activates the complete approved run. Simulation only. Operator audit stored.
* `POST /vision/analyze-image`: multipart `file,confidence=.5,camera_id=CAM02`. Returns existing real image model output plus normalized `detections` with source IDs/timestamps and `observation` traffic/crowd aggregate. `POST /vision/analyze-video`: same multipart plus `track=true`; returns `{job_id,status:"queued"}`. `GET /vision/jobs/{id}` returns `{job_id,status,progress,frame,total,result?,error?}`. POST `/{id}/pause`, `/resume`, `/cancel`. `GET /vision/results/{id}` returns stored observation. `GET /vision/samples` lists authorized local bundled sample image/video; POST `/vision/samples/{id}/analyze?camera_id=CAM02&confidence=.5` processes same real model pipeline. Network/RTSP sources unsupported until configured authorized stream ingestion exists; capability status explains this. Existing `/api/analyze/live` WS accepts optional camera_id; aggregates at most once/sec.
* `GET /settings` returns `{settings,capabilities}`; `PATCH /settings` accepts supported configuration values. `GET /system/status`, `/models/status` return capabilities and actual model/forecast/solver readiness. `GET /dashboard/analytics` calculated persistent counts, forecasts, runs, actions, observations. `GET /exports/{kind}?format=csv|json` kinds forecasts,traffic,recommendations,scenarios,operator-actions; exports database state. `GET /exports/scenarios/{id}?format=csv|json` exports one complete comparison.

`/network` also returns `stop_metrics:[{stop_id,boarding_demand,source,interval_minutes:30,timestamp,crowd_count,crowd_source,crowd_timestamp}]`; boarding values sum actual synthetic history at the latest half-hour, while crowds are null until real associated camera observations exist. `as_of` is the fixed recorded synthetic scenario origin; `updated_at` is request time.

Video jobs enter `encoding` after model inference while FFmpeg prepares a H.264/yuv420p faststart preview. Encoding permits cancellation and disables pause with an explanation. The final result has `video_encoding:"H.264",browser_playback:true`. An unchanged optimized plan also requires explicit whole-plan approval before activation. Every complete-plan approval and activation produces an operator audit record.

Activation preserves the complete selected scenario: fleet, reserve, bus seats, horizon, demand multiplier, event uplift, traffic level, maximum headway, costs and objective weights. `/dashboard/summary` exposes `raw_ml_forecast_demand`, `scenario_factor`, and `active_planning_inputs`. KPI `forecast_passenger_demand` equals the evaluator's adjusted demand, rounded up once per route; raw `forecast.forecasts[].predicted_passengers` remain ML outputs. `plan_approved` in fresh/stored run results reflects explicit whole-plan approval. `active_scenario_id` changes atomically on activation and prevents older parallel plans from overwriting the new active scenario. Public route `bus_capacity` and `capacity` reflect current global seats; `effective_max_headway_minutes` applies the global limit while `max_headway_minutes` remains the permanent route ceiling.

All geometric coordinates are illustrative canvas units, not GPS. `REAL_MODEL_DETECTION`, `SYNTHETIC_DEMO_DATA`, `ML_FORECAST` and `OPTIMIZATION_RESULT` provenance are explicit. Detected people are crowd estimates, not ticketed passenger boardings; physical speed and queue length are null when unsupported.

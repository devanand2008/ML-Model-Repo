# Route RAG assistant and blue road alternatives

Open `/passenger` for a journey or `/rag` for the model and operator advice workspace.

## Map use

1. Click one point on the map to select the start (A).
2. Click another point to select the destination (B). The app requests real road paths automatically.
3. Up to four distinct provider paths appear as blue lines; the selected line is thicker. Hover a line to see its road option, distance and profile minutes. Click a line or card to select it manually.
4. The routing request uses `alternatives=3`: one primary route and up to three alternatives. OSRM may return only one route, which the UI labels explicitly. No straight lines, duplicate paths or invented detours are added to claim multiple ways.
5. **Pick origin** and **Pick destination** edit a point. **New map journey** clears the journey and cancels pending results. GPS and destination search remain available.
6. With automatic selection enabled, traffic monitoring ranks the provider paths every five seconds. Clicking a route manually disables automatic switching. All alternatives remain visible when a route set first loads; choosing a route fits that path.

Road travel-time values are profile estimates. Camera comparison weights do not establish a live ETA or a guaranteed traffic-free road. [OSRM route documentation](https://project-osrm.org/docs/v5.24.0/api/#route-service) describes alternatives and their availability.

A live provider check returned two distinct paths for start `11.6649, 78.1460` and destination `11.6940, 78.1630`. These are example coordinates for trying the map, not verified bus stop locations. Route availability can change with provider data.

## Local RAG pipeline

The assistant combines:

- A fitted **TF-IDF vector retrieval model** with cosine similarity. It searches nine local traffic, speed, map and service-rule documents together with the current journey's path summaries and usable live camera observations. Each result exposes its source ID and retrieval score, which is relevance rather than prediction confidence.
- **Google FLAN-T5-small**, a local instruction-tuned encoder/decoder language model. Pinned revision: `0fc9ddf78a1e988dac52e2dac162b0ede4fd74ab`. Safetensors weights are installed under `weights/route-rag/flan-t5-small`; no cloud API key is required. Queries and retrieved context stay on the laptop server.
- **Evidence-constrained generation**. Question matching narrows the retrieved candidates to journey recommendations, speed, forecasts or bus-review constraints. A token-prefix tree restricts the model's output to complete paragraphs from the retrieved source candidates. Every neural answer is validated against the exact source text. This intentionally selects a supported explanation rather than allowing free-form text to invent roads, speeds, distances or service approvals.
- A separate structured road recommendation from the existing camera-pressure ranking. The model's words never select an official bus route, approve a recommendation or activate a plan.

The source model is [google/flan-t5-small](https://huggingface.co/google/flan-t5-small), licensed Apache-2.0. Retrieval follows [scikit-learn TF-IDF](https://scikit-learn.org/stable/modules/generated/sklearn.feature_extraction.text.TfidfVectorizer.html). This project integration is not a new fine-tune and does not claim evaluated citywide traffic accuracy.

## Journey and bus questions

After choosing endpoints, use **Route evidence assistant** beside the map. Example questions: “Why should I change my route?”, “What does the bus speed warning mean?” and “Can a bus use this alternative?”. The answer shows its model mode, source, current structured recommendation, evidence timestamp and source excerpts.

Journey advice uses a short-lived opaque provider context generated by the server. It contains actual OSRM paths and retains the current selection. The assistant does not accept a caller's invented path geometry, distance, ETA or traffic report as retrieved evidence. The monitor uses the original server paths when this context is supplied. Contexts are memory-only, limited to 128, and expire after 15 minutes without use or on server restart; replan if expired.

Traffic answers expire in the UI after 20 seconds. **Select recommended road route** requires an explicit click, an unexpired answer and agreement with the latest map recommendation. Bus advice disables this action and requires operator review. The assistant never changes an operating plan.

For a bus, `/rag` offers a bus selector and links to `/passenger?bus_id=BUS005&advice=bus`. Private bus advice retrieves the assigned service, configured stop IDs, variant and review rules. Required-stop information comes from the project's illustrative network and is labeled demo data. Real bus routing needs verified stops, road restrictions and operator checks. Assigned drivers can use the embedded bus-advice option after signing in through the Driver dashboard; admin/head-office users can use the RAG workspace. Interior CCTV, safety evidence and credentials are excluded from public retrieval.

## Startup and model availability

The Windows full-app launcher checks the RAG dependencies and downloads the pinned model once if its manifest is absent. `Setup-Route-RAG.bat` also prepares it explicitly. Model loading is lazy; it does not create an additional web server. Missing weights or a model error returns a clearly labeled retrieved-source fallback, while routing remains available.

Generation runs on a separate single-worker executor with a two-request admission limit and a timeout, preserving camera/ASGI responsiveness. CPU performance depends on hardware. A real local inference check selected the GPS-speed source in about 2.3 seconds after loading on this laptop; this is an observed check, not a latency guarantee.

## API

- `GET /api/public/rag/status`: retriever, generator, installed/loaded status and source count.
- `POST /api/public/rag/ask`: `question` (3–800 characters), optional `route_context_id`. Public route explanations cannot request private bus fields.
- `POST /api/rag/bus-advice`: the same fields plus `bus_id`; admin, head-office or the assigned driver is required.
- `POST /api/public/navigation/routes`: returns `route_context_id` alongside distinct provider paths and selected/recommended IDs.
- `POST /api/public/navigation/monitor`: optionally accepts that context to re-rank its verified paths. It retains the current selection and refreshes the context lifetime.

Sources are assembled fresh on each request; stale or recorded camera detections are excluded from live evidence. Current route comparisons and the recorded-demo option remain explicitly labeled. Generation uses trusted retrieved paragraphs and no service-action tools.
